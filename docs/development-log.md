## Day 1 · 2026-09-21

**定题。** 广告成片：需求 → 脚本 → 合规 → 分镜 → 生图 → 质检 → 生视频 → 成片，全部跑在一台 DGX Spark 上。理由是未发布新品素材不能上云，以及按条计费让反复修改变贵。

**选模型。** 在 Hugging Face 上逐个核对了体积：
- Nemotron 3.5 Lightning 30B-A3B NVFP4 为 21.6 GB，官方另有为 DGX Spark 调优的 DSpark 投机解码权重 1.3 GB，模型卡里有单机 Spark 的 vLLM 配方。模型卡列出的支持语言不含中文。
- Step3-VL-10B-FP8 为 15.1 GB。
- Step-3.7-Flash 的 NVFP4 版 129 GB，超过本机 121.7 GB 统一内存；GGUF IQ4_XS 为 105 GB，加视觉投影和运行时约 116 GB，和扩散模型无法共存。决定走 API，并在记录中标注 cloud。
- 结论：Nemotron 做规划和英文提示词，StepFun 做中文和看图，正好对上“内部用英文、对用户用中文”的分工。

**踩坑。**
- `docker stats` 在 GB10 上看不到 CUDA 占用：一个实占约 100 GB 的推理容器只显示 4.3 GiB。此后一律以 `/proc/meminfo` 的可用内存为准，并写进了 `spark-model-scheduler`。
- 代理间歇性 503，Hugging Face 直连几乎为零；改用 hf-mirror 直连实测约 43 MB/s。
- DeepSeek Harness 的 `sdk-minimal` 配置只带 DeepSeek 专用适配器，调本地 OpenAI 兼容端点返回 HTTP 400。本地模型应走“自定义提供方 + openai-completions”，待验证。

**写代码。** TypeScript CLI `cinefoundry`（10 个子命令）、Studio 看板、4 个 ComfyUI 工作流模板、9 个 Skill 和 20 条评测任务。16 个测试通过，其中端到端测试用真实 ffmpeg 加 ComfyUI 桩服务，从立项走到成片。

**实测数据。** 本机统一内存 121.7 GB；内存预算 Nemotron 30 + Step3-VL 20 + ComfyUI 45 = 95 GB，预留 10 GB 后余量 16.7 GB。

**下午：两个模型在 Spark 上真实跑起来。**
- 本机 Docker 通过 CDI（`nvidia.com/gpu=all`）暴露 GPU，没有注册 `nvidia` 运行时，compose 里的 `runtime: nvidia` 直接报错，改成 CDI 设备声明。
- Nemotron 一次启动成功。实测端到端解码 98–106 tok/s，工具调用 1.0 s 且参数正确；服务实占约 35 GB，比计划的 30 GB 多，预算表按实测改。900 个 token 全部用在推理上、正文为空，说明 `max_tokens` 要给够。
- Step3-VL-10B-FP8 连续崩溃重启。第一层原因是 DeepGEMM 的 FP8 内核在 GB10 上断言失败（Unknown SF transformation），设 `VLLM_USE_DEEP_GEMM=0` 解决。第二层原因是我给的内存比例 0.17 只剩约 2 GiB 给 KV cache。先试着降上下文长度，降了两次都差一点，方向错了；改成把比例提到 0.20，KV cache 47,616 token，32K 上下文保住。
- `cinefoundry qa` 在本地 Step3-VL 上跑通：同一张图，要求相符给 90 分通过，要求不符给 30 分拒绝并说出缺了什么。首次 26 s，之后 10 s。
- 两个 LLM 常驻后可用统一内存 47.6 GB，够扩散模型用。

**README。** 横幅改成 ANSI Shadow 方块字，方块画成矩形、文字转成 Google Sans Code 轮廓，不依赖访问者字体。架构图用 archify 生成，showcase 档 9/9 通过；横向五列放进 README 后字太小，改成竖向主线。截图时抹像素去工具栏连错两次，最后改为在临时副本里用 CSS 隐藏控件。

**明天。** 启动 ComfyUI，过 `cinefoundry doctor`；生成第一张首帧和第一段视频并记录耗时；接通 Harness 到本地模型。

## Day 1（续）· 傍晚到夜里：第一支成片，以及它暴露的一切

**ComfyUI 起来了。** 镜像直接建在 vLLM 镜像上，复用已经在 GB10 上验证过的 PyTorch 2.13 + CUDA 13。清华镜像缺 ComfyUI 示例模板包的一个新子包，改成不带子依赖安装。`cinefoundry doctor` 对着真实服务把 5 个工作流模板逐节点核对，全过。

**第一批真实数字。** Qwen-Image 首帧 1080×1920：首次 45.8 s，之后 22.7 s。Wan2.2 5B 的 5 秒 720p 片段 365 s。罐身上的“冷”字在整段视频里没有变形。但我要的是“泠”，模型画成了“冷”——生僻字靠不住。

**决定不依赖外部 Agent 框架。** 写了 Cinefoundry 自己的智能体运行框架，后来定名 **Cinefoundry Harness**（Harness 是业界对智能体运行框架的通称，）：八个阶段由代码保证顺序，每个阶段交给一个带 Skill 的子智能体，产出先过确定性校验。

**踩坑连环。**
- Nemotron 开着思考时，脚本和分镜阶段把 8000–10000 token 的额度全用在推理上，正文为空。关掉思考 0.3 s 出结果，改由校验器和重试兜底。
- Step3-VL-10B 关不掉思考，约 18 tok/s。让它做文字审稿，两次都在 5 分钟超时线上耗尽额度。结论：它只负责看图；文字审稿换成独立的 Nemotron 审稿智能体。
- 模型为了不超字数，把口播写成 4 个字。过校验不等于写得好，补了 8 字下限。

**第一支端到端成片：1453 s。** 质检闭环真实触发 4 次重生成。然后我看了成片的三张首帧，结论是不及格：产品在镜头间变了样；“气泡细腻”被画了两遍；风格词里的“50mm”被当成文字画进了画面；而质检给这些图打了 90 分。

**重做视觉流水线。** 先生成产品定妆图并过质检，所有镜头用带参考图的编辑模型生成；画面里不再让模型画字，标题字幕在后期用真字体排版；质检对照定妆图，多余文字、乱码、产品不符一票否决。第一张新首帧出来，罐子和定妆图是同一个——这条路对了。

**14B 视频模型。** Wan2.2 I2V A14B 配 4 步 LoRA，实测 353 s，不比 5B 慢，画面更锐、运动更真，设为默认。它会自作主张加一只手去拉拉环，所以产品镜头的提示词要写明“画面内不出现人和手”。

**把自己坑了两次。**
- 让对比评测和成片任务并行，GPU 驱动报内存分配失败，成片任务超时崩掉。更本质的问题是：我写了“内存调度”Skill，导演运行时自己却没执行它。现在导演在每个阶段切换时释放上一阶段的扩散模型。
- 为了防超时把质检的输出上限压到 1800，结果 StepFun 思考完就没额度给结论了，整个任务又崩一次。质检不能是单点故障：现在失败会用更大的额度重试，仍不行就把该帧标为“未验证”继续走，并如实记录。

**对比评测。** 同一个模型、8 个创意各 2 轮、只看第一次作答：脚本一次合格 0/16 → 6/16，分镜 0/16 → 8/14；分镜平均违规 8.0 → 0.71。带 Skill 的一组口播偏短，说明脚本 Skill 只写了上限没写下限，已补。

**还差什么。** 成片没有声音；每个镜头只生成一次，没有多候选选优；演示视频还没录。

## Day 3 · 2026-09-23

**排队脚本把自己等死了。** 昨晚的语音测试和咖啡重剪都没跑：排队脚本里“等 harness 结束”的 `pgrep -f "dist/cli.js harness"` 匹配到了生成这个脚本的那条命令本身——heredoc 的全文留在父 shell 的命令行里，只要子进程活着它就在。等了十六个小时。改法：排队脚本用文件写入而不是 heredoc，匹配模式锚定进程名开头（`^node dist/cli.js harness`）。

**Step-Audio-EditX 第三次失败、第四次开跑。** 第二次死在只读挂载；第三次死在注意力后端：它的源码用环境变量 `VLLM_ATTENTION_BACKEND=TRITON_ATTN` 指定后端，而 vLLM 0.27 已不认这个变量，默认选了 FLASH_ATTN，模型的 alibi 注意力在这个后端上不支持。改为在建引擎时传 `attention_backend`，作为可重复应用的本地补丁挂在包装脚本里。

**咖啡第五版进 README。** 画面稳定、产品一致；标题“开罐”按新规则改为“晨光”后重剪。镜头 1 的分镜要求“咖啡粉在热水中翻涌”，四个候选都画成了咖啡豆，按规则保留最高分继续并写进交付报告的待确认事项——这条如实写进了 README。交付报告此前在 Harness 里写得太早（总耗时为空、重生成次数为零），改为在最终记录之后再写一次。

**演示视频改为自动生成。** `scripts/demo-reel.py` 从仓库自己的产物（运行记录、被拒和通过的首帧、四支成片、消融结果）画卡片、合成旁白、拼成约三分半钟的成片；数字全部从文件读取。成片或声音一变，重跑一次即可。

**键盘，第三到第五版。** v3 暗棚单色光对了，但三个镜头都有手、两镜同为“微距慢推”、must_show 写成了动作、定妆图把键盘立了起来、视频里灯光漂成蓝紫。v4 出现金色键盘（分镜写了“黄铜质感”）和半透明的“幽灵键盘”叠影。每一处都成了规则：3C 最多一个手镜头、任意两镜不得同景别同运镜、must_show 不得写动作、定妆图按品类定姿态、分镜不得重新描述产品外观、视频负面提示词按品类禁止彩虹循环和叠影、质检拒绝多余品牌字与彩虹光。v5 进了 README。

**提速：两条路走不通，一条路有用。** 另一个会话留下的笔记判断“每段视频有 150 秒是内存挤占造成的权重搬运”，于是试了 vLLM 睡眠模式：可用内存从 47 GB 升到 104 GB，视频每段仍是 340 秒，两个语言模型却慢了一个数量级，唤醒后还要重载权重（否则 Nemotron 会复读“后汉书”）。判断是错的，已回退。Step3-VL 跳过推理能把质检从 74 秒压到 3 秒，但判定变得不可信，也弃用。有用的是首帧段四项：按视频尺寸出图、第二候选懒生成、缩图送审、审图与生图流水化。首帧段 1141 → 524 秒，总时长 2256 → 1842 秒；一次镜头返工就能把省下的时间吃回去。

## Day 4 · 2026-09-24
